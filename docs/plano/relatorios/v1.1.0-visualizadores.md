# Relatório — v1.1.0: Visualizadores de arquivos

**Data:** 2026-11-17
**Branch:** `feat/v1.1.0-viewers`
**Pedido:** "Permitir abrir outros tipos de arquivo como pdf, visualização de .md formatadinho, imagens de todos os formatos, vídeos, documentos."

## Entregas

### Servir arquivos locais com segurança

- Protocolo privilegiado `agzos-file://` (`standard`, `secure`, `stream`, `supportFetchAPI`), registrado
  antes do `ready` e tratado com `protocol.handle` em `src/main/lib/file-protocol.js` (módulo puro, sem Electron).
- Formato: `agzos-file://local/<caminho absoluto com cada segmento em encodeURIComponent>`
  (Windows: `agzos-file://local/C%3A/…`). A query (`?v=mtime`) só fura cache.
- Só serve caminhos aprovados pelo **mesmo path-guard** do `ipc/fs.js` (resolve symlinks e `..`).
  Fora do guard → **403**; URL inválida/host errado/NUL → 400; inexistente ou diretório → 404.
- Range de bytes (206 / 416) para streaming de vídeo e áudio; MIME por extensão; `nosniff`.
- CSP alterada só no necessário: `img-src … agzos-file:`, `media-src agzos-file:`,
  `frame-src 'self' blob: agzos-file:`. Nenhum `file://` novo foi liberado. `object-src` não foi
  necessário (o PDF funciona dentro do `<iframe>`).
- Novos IPCs: `fs:openPath` e `fs:reveal` (app padrão / revelar na pasta, ambos com guard),
  `fs:allowDropped` (arquivo solto do SO; o preload obtém o caminho com `webUtils.getPathForFile(File)`,
  então o renderer não consegue forjar um caminho arbitrário) e `fs:readFile(p, { detectBinary })`
  (byte NUL nos primeiros 8 KB → `{ binary: true }`, inclusive para arquivos acima de 5 MB).
- `webPreferences.plugins: true` na janela principal (visualizador de PDF do Chromium).

### Abas de visualização

- `editor.openFile` roteia pelo tipo (`viewers/detect.js`): texto/Markdown vão ao Monaco; os demais
  viram aba de visualização **sem modelo Monaco**, com ícone e título normais, fechando e alternando como
  qualquer aba. Explorer, Quick Open, abas, diálogo "Abrir Arquivo", links do agente e **arrastar do SO**
  usam o mesmo caminho.
- Abas de visualização nunca salvam (Ctrl+S é ignorado) e não entram como contexto de arquivo no chat.
- Mudança externa (git/agente) numa aba de visualização recarrega a mídia (mtime novo).
- "Abrir como texto" converte a aba no lugar (SVG, CSV, binário, Markdown).

### Por formato

| Formato | Resultado |
|---|---|
| png, jpg/jpeg, gif, webp, avif, bmp, ico, apng | `<img>` com zoom ajustar/100%/+/−, Ctrl+roda, fundo xadrez, rodapé com dimensões, tamanho e tipo |
| svg | Igual, **sempre como `<img>`** (nunca inline no DOM) + "Abrir como texto" |
| heic, heif, tiff, psd, raw (cr2/nef/arw/dng…) | Tela "Formato sem pré-visualização" com "Abrir no app padrão" e "Revelar na pasta" |
| mp4, webm, ogv, mov, m4v (mkv/avi tentam) | `<video controls>` com streaming por Range; erro de codec → tela de fallback |
| mp3, wav, ogg, oga, flac, m4a, aac, opus | `<audio controls>`; erro → fallback |
| pdf | Visualizador embutido do Chromium em `<iframe>` (funciona no Electron 32 com a CSP acima) |
| md, markdown | Abrem no editor. Botões na barra das abas + comandos "Markdown: Abrir Pré-visualização ao Lado" (Ctrl+Shift+V) e "…na Aba Atual" |
| csv, tsv | Grade com rolagem virtual (parser próprio, delimitador detectado `,`/`;`/tab/`|`), cabeçalho fixo e "Abrir como texto" |
| docx, docm, dotx | Renderizado com docx-preview, somente leitura: zoom (ajustar à largura/100%/±/Ctrl+roda), rolagem, páginas, tabelas, imagens embutidas |
| xlsx, xlsm, xlsb, xls, ods | SheetJS: abas por planilha, colunas A/B/C e linhas numeradas fixas, grade virtual, aviso acima de 50 mil células |
| doc, odt, rtf, pptx, ppt, odp | Tela de fallback (no backlog) |
| binário desconhecido | Tela "Arquivo binário" com tamanho, "Abrir no app padrão", "Revelar na pasta" e "Abrir mesmo assim como texto" |

### Markdown

- `marked` + `DOMPurify` (nova função `sanitizeMarkdown` em `markdown.js`, reaproveitada pelo chat).
- Estilo de documentação (títulos com régua, tabelas zebradas, citações, checkboxes de tarefa, código).
- Realce dos blocos de código com `monaco.editor.colorize` (mesmo tema do editor).
- Imagens relativas resolvidas para `agzos-file://` (`/x.png` é relativo à raiz do workspace, como no GitHub).
  Imagens remotas não carregam (CSP) — ficam com o texto alternativo.
- Links: `http(s)` abrem no navegador via `app.openExternal`; `#âncora` rola até o título; caminhos
  relativos abrem no editor.
- Pré-visualização ao lado: painel dividido que atualiza ao digitar (debounce 150 ms) e acompanha o
  scroll de forma proporcional; segue a aba Markdown ativa e some em abas que não são Markdown.
- Temas dark/light/monokai respeitados (só variáveis de tema).

### Outros

- Ícones novos no `icon-theme.js`: avif, bmp, apng, heic/heif, tiff, psd (imagem), mov/m4v/mkv/avi/ogv
  (vídeo), ogg/oga/flac/m4a/aac/opus (áudio), odt/rtf, ods/tsv, ppt/pptx/odp.
- Correção: "Revelar no Explorer do SO" no menu da árvore chamava `openExternal('file://…')`, que o
  main recusa (só http/https). Agora usa `fs:reveal`.
- Soltar arquivo do SO não navega mais a janela para `file://`.

## DOCX e XLSX (segunda entrega)

Aprovado depois da primeira entrega. Dependências: `docx-preview@^0.4.1` (Apache-2.0, traz `jszip` 3.10.2)
e `xlsx@0.20.3` (SheetJS CE, Apache-2.0, tarball de `cdn.sheetjs.com` — a versão 0.18.5 do npm tem CVEs).

- **Carregamento:** `tools/setup-vendor.js` copia `jszip.min.js`, `docx-preview.min.js` e
  `xlsx.full.min.js` (com LICENSE) para `src/renderer/vendor/`. O renderer os carrega **sob demanda**
  (`viewers/lazy-script.js`) na primeira abertura de .docx/.xlsx; nada muda no boot. Durante o carregamento
  `window.define` fica escondido, porque o loader AMD do Monaco faria os UMD se registrarem nele.
- **Bytes do arquivo:** novo IPC `fs:readBinary` (guard, limite de 50 MB).
- **CSP:** nenhuma mudança. As imagens do DOCX saem como `data:` (`useBase64URL`), os estilos são inline
  (já permitidos) e os scripts vêm de `'self'`. O E2E verifica que não há violação de CSP no console.
- **DOCX:** somente leitura, zoom e "ajustar à largura" automático quando a página não cabe. Links do
  documento nunca navegam a janela (`http(s)` abre no navegador).
- **Planilhas:** `viewers/sheet-model.js` (puro) transforma o workbook em linhas formatadas por aba;
  `viewers/grid.js` desenha só as linhas visíveis (linha de 24 px), com cabeçalho e coluna de números fixos.
  O CSV/TSV passou a usar a mesma grade, então o corte de 5000 linhas saiu (fica o limite de 5 MB de leitura).
  Aviso acima de 50 mil células; acima de 2 milhões as linhas excedentes não são carregadas (aviso diz quantas).
- **Tamanho adicionado:** 1,2 MB em `vendor/` (xlsx.full 952 KB, jszip 98 KB, docx-preview 76 KB).
  Como estão em `dependencies`, o electron-builder também empacota os pacotes de `node_modules`
  (xlsx 7,8 MB, jszip + pako/lie/… ≈ 2,1 MB, docx-preview 1 MB ≈ 11 MB descompactados), que o app não usa
  em tempo de execução — sugestão no backlog: excluí-los de `build.files`.
- **Testes:** unit `viewers-office.test.js` (engines por extensão, letras de coluna, janela da rolagem
  virtual, workbook→abas com SheetJS real, corte por células, limiar de aviso) e `fs:readBinary`;
  E2E com fixtures geradas no próprio teste (`test/e2e/office-fixtures.js`: .docx com tabela, link e imagem;
  .xlsx com 2 abas; .xlsx de 60 mil células; .ods) e checagem de violação de CSP no console.
- **Verificação final:** `npm run check` 572/572 (lint limpo); E2E de visualizadores 17/17; suíte E2E completa 98/98 (9,5 min).

## Desvios e observações

- `.md` em "pré-visualização na aba atual" troca o editor pela pré-visualização **na mesma aba**
  (botão "Abrir como texto"/"Editar texto" volta), em vez de abrir uma segunda aba "Preview".
- Ctrl+Shift+V segue o pedido (ao lado); no terminal e em inputs continua sendo colar.
- mkv/avi entram como vídeo e caem no fallback quando o codec não é suportado (detecção por erro do `<video>`).
- Arrastar do SO não tem E2E (o Playwright não consegue criar um `File` com caminho real; o `webUtils`
  devolve vazio para arquivos sintéticos). A lógica de liberação está coberta no unit de `fs:allowDropped`.
- Arquivos soltos do SO fora do workspace são liberados no guard (só o arquivo, nunca a pasta),
  do mesmo jeito que o diálogo "Abrir Arquivo".
- Imagens remotas no Markdown seguem bloqueadas pela CSP (decisão de privacidade; item no backlog).
- Primeira entrega sem dependência nova; a segunda adicionou docx-preview e xlsx (aprovadas).
