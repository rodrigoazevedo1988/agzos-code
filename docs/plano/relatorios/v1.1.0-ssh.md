# Relatório — 1.1.0: atalho rápido de SSH

**Executor:** Claude Opus 5.5 (agente Q)  **Data:** 2026-11-17  **Branch:** feat/v1.1.0-ssh  **PR:** — (sem push)

## Resumo
Botão remoto (`><`) no início da status bar abre o seletor "Selecione uma opção para abrir uma conexão remota".
Ele lista os hosts do `~/.ssh/config` (com `Include`) e oferece conectar, adicionar host, abrir o config e WSL (só no Windows).
"Abrir pasta remota via SSH" aparece desabilitado com o selo "Em breve (1.2.0)".
Conectar abre uma sessão de terminal rodando o `ssh` do sistema. O main monta os argumentos em array, sem shell intermediário.
A pasta remota (SSH/SFTP) não foi implementada: fica para a 1.2.0.

## Decisões e desvios
- **Conexão via `opts.ssh`, não via `{ shell, args }` genérico.** O renderer manda `{ alias }` ou `{ user, host, port }`. O main valida (`buildSshArgs`), acha o binário (`findSsh`) e ignora `shell`/`args` vindos do renderer. Assim o renderer nunca escolhe argumentos livres.
- **`ssh` não entrou na `SHELL_ALLOWLIST`.** Ganhou uma `SSH_ALLOWLIST` própria. Com isso, `opts.shell = 'ssh'` continua rejeitado (há teste para isso).
- **Validação:** host = hostname `[A-Za-z0-9_][A-Za-z0-9._-]*` ou IPv6 entre colchetes. Usuário = `[A-Za-z0-9_][A-Za-z0-9._-]*`. Porta = 1–65535. O usuário é opcional. Nada pode começar com `-`; espaço, `;`, `|`, `$`, crase, aspas e quebra de linha são rejeitados. Não há `--` antes do destino porque a validação já impede a injeção de opções.
- **IPC extra `ssh:parseTarget`:** o diálogo do renderer usa a mesma validação do main, sem duplicar o código.
- **`ssh:addHost` usa `appendFile`, com só o sufixo novo.** O arquivo existente nunca é reescrito e as permissões dele não mudam. Se o arquivo não existir, ele é criado com `wx` e modo 600. A pasta `~/.ssh` é criada com 700. Apelido duplicado é rejeitado.
- **`ssh:configPath`** cria o config se faltar e libera no guard **só** esse arquivo. Teste confirma que `~/.ssh/id_rsa` e a pasta `~/.ssh` continuam bloqueados.
- **Hosts com alias inseguro** (ex.: `Host "a b"`) são omitidos do seletor.
- **`showPicker`** ganhou `title` (vira o placeholder, como no quick pick do VS Code) e, por item, `icon`, `description`, `badge`, `disabled` e `id`. Item desabilitado não executa nem por clique nem por Enter (`quickOpenEnterAction`).
- **Cor de destaque:** a status bar inteira já usa `--accent` como fundo. Por isso o estado "conectado" usa `--accent` escurecido (`color-mix` com preto) com um filete claro embaixo, e o texto "SSH: <host>". Sem conexão, o botão fica com um fundo levemente mais escuro, como no VS Code.
- **Estado do botão:** `terminal.js` dispara o evento `agzos:terminal-active` a cada render do chip, com `{ ssh, exited }` da sessão ativa. O destaque só aparece com sessão SSH ativa e viva.
- **Split de uma sessão SSH** abre outra conexão SSH ao mesmo alvo. **Reiniciar** (Enter depois de encerrar) reconecta.
- **`ssh` ausente:** o renderer checa `sshAvailable` antes de criar a sessão e mostra um toast com a instrução de instalação. No Windows, a instrução é o recurso opcional "Cliente OpenSSH". O main também devolve `code: 'ssh-missing'` com a mensagem.
- **e2e:** com `AGZOS_TEST=1`, o main grava `global.__agzosLastSpawn = { shell, args, mode, profileId }` e o teste lê via `app.evaluate`. Os alvos apontam para um servidor TCP local que aceita a conexão e não responde. Assim o ssh fica vivo esperando o banner, sem depender de rede externa.
- **Correção fora do escopo (terminal):** matar sessões em sequência rápida às vezes gerava `pageerror` `Cannot read properties of undefined (reading 'dimensions')`. Era o refresh do viewport do xterm agendado em rAF depois do `dispose`. Reproduzi na base sem as minhas mudanças: 2 de 5 execuções falharam. Agora `killTerminal` remove o host na hora e faz o `dispose` no próximo frame. Depois disso, 6 de 6 execuções passaram.

## Problemas encontrados
- OpenSSH lê `~/.ssh/config` do `getpwuid`, não de `$HOME`. No e2e com `HOME` temporário, `ssh prod` usa o config real do usuário. O teste verifica só os argumentos do spawn, não a resolução do alias.
- Sem node-pty (modo pipe), o ssh avisa "Pseudo-terminal will not be allocated". Isso é esperado no fallback.

## Dúvidas para o sênior

- Vale exibir `IdentityFile` na descrição do host? Hoje mostro só `user@HostName:Port`.
