## O que foi feito

### Motor (`src/main/modules/history/`)
- `store.js` — `createHistoryStore({ dir, getLimits, now })`: cópia em
  `userData/local-history/<sha1(caminho)>/<id>` + `index.json` (`{ path, entries: [{ id, ts, size, origin, hash }] }`).
  `id` = timestamp em ms (sufixo `-N` se repetir no mesmo ms). Pasta 0700, arquivos 0600, escrita
  atômica (tmp + rename). Conteúdo igual ao da última versão não duplica (sha1). Ignora binários
  (NUL nos primeiros 8 KB), arquivos > 1 MB, pastas e inexistentes. `record(path, origin, { content })`
  aceita o conteúdo explícito (cópia local de arquivo remoto). Índice corrompido → recomeça.
- `prune.js` — `planPrune(files, { maxPerFile, maxDays, maxTotalBytes, now })` puro: por arquivo,
  idade e total (apaga as mais antigas). O store faz varredura completa na 1ª gravação da sessão e
  quando o total em cache passa do limite; nas demais, só poda o arquivo gravado.
- `index.js` — instância única do main: `configureHistory`, `recordBefore(absPath, origin)` (nunca
  lança; respeita `modules.localHistory.enabled`), `getHistoryStore`, `sliderOptions`.
- `timeline.js` — `parseGitLog`, `gitLogArgs` (`-c core.quotePath=false log --follow -n N
  --format=… --name-only -- <arquivo>`, cwd = pasta do arquivo), `mergeTimeline` (mais antiga
  primeiro; empates mantêm a ordem do git), `parseVersionId` (`local:<id>` | `git:<sha>:<caminho no
  repo>`; nega `..`, absoluto, `\`, NUL), `buildTimeline`, `readVersion` (`git show <sha>:<caminho>`)
  e `createLru`.
- `io.js` — **ponto de troca para o remoto**: `readFileFor(path)`, `writeFileFor(path, buf)`,
  `runGitFor(root, args)`.
- `agent-tool.js` — `file_history(path)` (read).

### IPC (`src/main/ipc/history.js`, preload `window.agzos.history`)
`list(path)`, `timeline(path) → { items, git, truncated }`, `read(path, versionId) → { content }`,
`recordSave(path)`, `restore(path, versionId) → { checkpointId }`, `clear(path?)`.
Todo caminho passa por `guardOf(event.sender)`. Por janela: cache LRU de 50 MB dos conteúdos de
commit e o conjunto de versionIds conhecidos por arquivo (descartados no `destroyed`). Uma versão git
só é lida se fizer parte da linha do tempo **do próprio arquivo** (o renderer não consegue ler outro
caminho do repositório pelo versionId). `restore`: guarda o conteúdo atual (`externo`), checkpoint em
`userData/history-checkpoints`, escreve a versão byte a byte e registra a nova (`restaurar`).

## Pontos de troca para o remoto (I1)
1. `src/main/modules/history/io.js`: `readFileFor`, `writeFileFor`, `runGitFor` → `providerFor(path)`
   (`readFile`/`writeFile`/`exec('git', args, { cwd })`). O git roda com `cwd = path.dirname(arquivo)`
   (no remoto, `path.posix`).
2. `recordBefore(absPath, origin, { content })` já aceita o conteúdo: no remoto, os pontos de escrita
   devem passar o Buffer lido via provider (sem `content`, o store usa `fs` local).
3. `timeline.js` usa `path.dirname/basename`: trocar por `path.posix` para URIs `ssh://`.
4. O store guarda a cópia sempre localmente (chave = sha1 da URI), como pede a spec.

## Desvios
- Origem extra `restaurar` (além de `salvar|agente|vassoura|cofre|externo`) para a versão gravada pela
  restauração; o conteúdo anterior à restauração entra como `externo`. `externo` não tem outro gatilho
  (não há watcher de mudança externa nesta tarefa).
- Preload ganhou `timeline` e `recordSave` além de `list/read/restore/clear`.
- IDs do DOM com prefixo `file-timeline` porque o sprite do Lucide já tem `<symbol id="timeline">`.
- `restore` gera checkpoint (`userData/history-checkpoints`), mas não há canal de desfazer: a versão
  anterior fica no próprio histórico e pode ser restaurada pela linha do tempo.
- Conteúdo de commit é lido como UTF-8 (`runGit` usa `encoding: 'utf8'`); binários já são excluídos.
- Marcadores são espaçados por índice (em ordem de tempo), não proporcionais à data.
