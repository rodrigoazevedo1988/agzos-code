## O que foi feito

### Motor (`src/main/modules/envvault/`)
- `parse.js` — `parseEnv(text) → { entries: [{ key, value, line, quoted, exported }], eol }`, `setEntry`, `removeEntry`.
  `export`, aspas simples/duplas/crase, multilinha entre aspas, `KEY=a#b` mantém `a#b`, `KEY=a #c` → `a`,
  `KEY="x=y#z"`, CRLF preservado. `setEntry` mexe só nas linhas da chave e mantém o estilo de aspas e o comentário do fim da linha.
- `compare.js` — `compareEnv(example, entries) → { missing, extra, empty }`, `findExampleFile` (`.example` > `.sample` > `.template`).
- `detect.js` — `detectSecrets(text, { fileName, extraPatterns, allowlist }) → [{ line, column, rule, preview }]`.
  Regras: `private-key`, `aws-access-key`, `aws-secret-key`, `stripe`, `anthropic`, `openai`, `github`, `google-api-key`,
  `slack`, `jwt` (com `service_role`, ou ≥ 100 caracteres e sem `role: anon/authenticated`), `url-credentials`, `generic-secret`
  (chave com SECRET/TOKEN/PASSWORD/PRIVATE_KEY/API_KEY, Shannon ≥ 3.5, ≥ 16 caracteres). Placeholders, `process.env.X`/código,
  UUID, `sha512-…` e lockfiles (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `npm-shrinkwrap.json`, `bun.lock`) não disparam.
  `allowlist` aceita o valor ou o sha256 (hex, com ou sem `sha256:`). `preview` = 4 caracteres + `…`.
- `staged.js` — `scanStagedDiff` (só linhas `+`, numeradas pela linha nova do hunk, caminhos com quoting do git),
  `scanStaged(repoRoot)` via `git diff --cached` (funciona sem commits e em detached HEAD), `isRealEnvFile`.
- `commit-guard.js` — `createCommitGuard({ getSettings, userDataDir })` (`check`, `logOverride`, `options`), singleton
  `configureCommitGuard/getCommitGuard`, `commitCommandRisk` para o agente.
- `vault.js` — busca `.env*` (profundidade 3, sem `node_modules/.git/dist`, máx. 200 arquivos, 1 MB), listagem mascarada,
  edição pontual, geração/mescla do `.env.example`.
- `hook.js` — `installHook/removeHook/hookStatus` com o marcador `# agzos-envvault-hook`; o caminho vem de
  `git rev-parse --git-path hooks` (respeita worktrees e `core.hooksPath`). O script nunca imprime a linha encontrada.
- `agent-tool.js` — `env_check` (`kind: 'read'`) + gancho `commandRisk`.

### Integrações
- `ipc/git.js` `git:commit`: com `enabled && blockCommits`, varre o staged dentro da fila do repositório; achados (ou `.env` real
  staged, regra `env-file`) → `{ ok: false, error: { kind: 'secrets_detected', message, findings } }` (o `fail()` passa a carregar `findings`).
  `options.ignoreSecretsOnce` commita e grava `ISO\trepo\tarquivos\tregras` em `userData/envvault-overrides.log` (modo 0600, sem valores).
- `agent/tools.js`: ferramentas extras podem expor `commandRisk(command, { cwd, root })`; o preparo do `run_command` consulta os
  ganchos e, com motivo, marca `risky`/`riskReason`/`preview.reason` (o preparo só vira assíncrono quando algum gancho devolve Promise,
  ou seja, só para `git … commit`). O Cofre devolve `'commit com possíveis segredos'`.
- `ipc/envvault.js` (reescrito): todos os canais da spec + `envvault:undo`. `root` opcional (padrão: pasta recente); tudo via path-guard;
  `reveal`/`copy`/edições só aceitam arquivos `.env*`. Checkpoints em `userData/envvault-checkpoints/` (pasta 0700, máx. 20).
  `copy` usa `clipboard.writeText` no main.
- Painel Git (`git-panel.js`): diálogo "Commit bloqueado: possíveis segredos" (Cancelar com foco padrão, Remover do stage, Ignorar uma vez;
  clique num achado abre o arquivo na linha). Commit e Commit e Push usam o mesmo fluxo. Mostra só arquivo:linha, regra e preview mascarado.
- View no hub (`envvault.js` + `envvault.css`): cartão por arquivo, `••••••••`, revelar com clique longo (500 ms) ou Alt sobre a linha,
  some após `revealTimeoutSec`; copiar/editar (input vazio, sem pré-preencher)/remover/adicionar; selos `segredo`, `vazia`,
  `faltando (está no example)` (linhas-fantasma das chaves do example que faltam no arquivo), `não está no example`; resumo,
  "Verificar staged", "Instalar proteção pre-commit"/"Remover proteção", aviso de `.gitignore` com "Adicionar ao .gitignore".
  Após editar, o arquivo aberto recarrega por `handleExternalChange`. Comandos: "Agzos: Abrir Cofre .env",
  "Agzos: Verificar segredos no stage".

## Desvios da spec/plano

1. **Singleton do bloqueio de commit.** `ipc/git.js` recebe só `{ guard, accounts }` no `main.js`. Para não editar o `main.js`,
   `ipc/envvault.register` chama `configureCommitGuard(...)` e o `git.js` resolve `getCommitGuard()` na hora do commit (aceita
   também `commitGuard` injetado, usado nos testes).
2. **Gancho de risco genérico.** Em vez de `tools.js` importar o Cofre, a ferramenta extra expõe `commandRisk`; o `env_check` o
   carrega. Assim o gancho some sozinho quando o módulo está desabilitado (`getModuleTools`).
3. **`envvault:undo` existe no main mas não no preload** (o preload não podia ser editado). A view não oferece "Desfazer" ainda.
4. **Canais com `root` opcional** (`list`, `scanStaged`, hooks, `.gitignore`): a spec diz `list()`; o renderer passa
   `State.workspaceRoot` e, sem argumento, vale a pasta recente.
5. **`generateExample` com example existente** só acrescenta as chaves que faltam (vazias); nunca remove nem apaga valores-padrão escritos à mão.
6. **Regras com nomes próprios** (`aws-access-key`, `generic-secret`, `env-file`…); o renderer traduz para pt-BR.
7. **Correção fora do Cofre em `ipc/git.js`:** a cauda de `createQueue` rejeitava junto com a operação (gerava `unhandledRejection`)
   e nunca era limpa (comparava com a promise errada). Agora a cauda não rejeita e é removida no fim.
8. **Teste da Fase A ajustado** (`agent-tools.test.js`, "getModuleTools ignora módulo desabilitado e stub null"): esperava `[]` dos
   stubs reais; agora confere `env_check` presente/ausente conforme o módulo (no merge com a Vassoura, `clean_code` não quebra a asserção).
9. TDD: motor, IPC e ferramenta seguiram teste → falha → código. O diálogo do painel Git e a view foram escritos antes do e2e
   (`envvault.spec.js`), que passou na primeira execução depois de pronto.
