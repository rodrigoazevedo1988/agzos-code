## O que foi feito

### Motor (`src/main/modules/broom/`)
- `analyze.js`: `analyze(text, { fileName, rules, keepConsole, keepComments }) → { edits, error? }`
  com `ts.createSourceFile` (sem Program/type checker). Edições são intervalos de remoção sobre o
  texto original; `Edit = { id: 'rule:start', start, end, rule, line, preview, keepStart?, keepEnd? }`.
  - Remoção de linha inteira inclui recuo, comentário de fim de linha e a quebra (`\n` ou `\r\n`).
  - BOM: analisado sem ele e as posições deslocadas; o BOM nunca é removido.
  - Instrução que é corpo de `if`/laço sem chaves não é removida (mudaria a semântica).
  - Edições sobrepostas são deduplicadas (contidas saem, sobreposição parcial é aparada; a união
    não muda) com busca binária.
  - `unusedImports` ignora usos que estão dentro de trechos removidos por outras regras (ex.: import
    usado só num `console.log`), para a limpeza ser idempotente; nomes citados em JSDoc mantido
    contam como uso.
- `apply.js`: `applyEdits(text, edits)` (pura; ordem decrescente; sobreposição mantém o maior).
- `cache.js`: LRU (200) por `path|mtimeMs|size|rulesHash`.
- `engine.js`: motor no main compartilhado por IPC e agente (cache, plano de limpeza, gravação que
  recusa se o arquivo mudou desde a leitura). `typescript` só é carregado no worker.
- `worker.js`: handlers `broom.analyze`, `broom.analyzeMany` (cancelável entre arquivos) e
  `broom.listFiles` (lista e lê os arquivos no worker).

### IPC (`src/main/ipc/broom.js`)
Canais da spec. Respostas: `analyzeFile → { count, byRule, edits, error? }`,
`cleanFile → { checkpointId, removed, error? }`, `scanWorkspace → { files, truncated, cancelled }`
(+ eventos `progress`/`done`/`error`), `cleanWorkspace → { checkpointId, files, removed }`,
`cancel → boolean`, `undo → { restored, errors }`. Checkpoints em `userData/broom-checkpoints/`
(máx. 20, `createCheckpointStore`). Arquivos alterados (limpeza e desfazer) avisam o editor pelo
evento já existente `agent:event` `{ type: 'file_changed', path }` (requestId `'broom'`), que recarrega
a aba limpa ou mostra a barra de conflito se estiver suja.

### Interface (`src/renderer/scripts/broom.js`, `styles/broom.css`, `#status-broom`)
Status bar `🧹 N`, preview em diff com "Limpar", pedido "Salvar e limpar"/"Cancelar" para arquivo
sujo, view no hub (Analisar workspace, progresso, Cancelar, lista com `−N` e chips por regra,
checkbox, clique abre o diff, Limpar selecionados, toast com Desfazer), 3 comandos da paleta com os
labels exatos, menu de contexto do Explorer (arquivo → preview; pasta → scan só da pasta) e do
editor (ação do Monaco), badges `−N` no Explorer para arquivos analisados e do último scan.

### Agente (`src/main/modules/broom/agent-tool.js`)
`clean_code({ path, rules? })`, `kind: 'write'`. Arquivo ou pasta (até 200 arquivos analisáveis),
`preview.diff` (pasta: diff combinado com cabeçalho por arquivo + `preview.files`), checkpoint da
conversa antes de gravar, `meta: { files, removed, byRule }`, `changed` para o `file_changed`.

## Desvios da spec/plano

- **Edição com trecho preservado:** `if (false) {…} else {…}` vira uma edição com
  `keepStart/keepEnd` (remove tudo menos o conteúdo do else), em vez de duas remoções soltas.
  `applyEdits` e o renderer tratam esse formato.
- **Worker lê os arquivos do scan:** `broom.analyzeMany` aceita `{ path }` sem `text` e há um handler
  extra `broom.listFiles`. Motivo medido: nesta VPS `fs.promises.readFile` custou ~2 ms por arquivo
  no main (5000 arquivos ≈ 10 s); lendo no worker o scan de 5000 arquivos caiu para ~1,5 s e o main
  não faz I/O em massa. A raiz continua validada pelo path-guard no main; links simbólicos não são seguidos.
- **`scanWorkspace(requestId, root?)`:** segundo argumento opcional (pasta do menu de contexto). Sem
  ele, usa a pasta aberta (mesma regra do agente: `recentFolders[0]` liberada no guard).
- **Cancelamento:** o evento final é `done` com `cancelled: true` (resultado parcial), não um tipo novo.
- **Cache invalidado ao salvar:** a chave inclui `mtime|size`, então salvar já invalida; não há
  canal novo de invalidação (o preload não foi editado). `cleanFile`/`undo` invalidam explicitamente.
- **Build:** além do que o plano lista, exclui `typescript/lib/{tsc.js,_tsc.js}` (6 MB) e
  `typescript/bin/**`; não são usados em runtime.
- **Diretivas mantidas:** além das da spec, `@__PURE__`/`#__NO_SIDE_EFFECTS__`, `istanbul/c8/v8
  ignore`, `@vite-ignore`, `@flow`, `/* global … */` e `webpack*:` em geral.
- **Comentário de fim de linha:** ao remover uma instrução de linha inteira, o comentário no fim da
  mesma linha sai junto (ex.: `console.log(x); // debug`).
- **Fixture `server.js`** tem `/* eslint-disable */` no topo (o lint do repositório roda em
  `test/**`); o teste espera a diretiva mantida.
- **`test/unit/agent-tools.test.js`** (Fase A) foi ajustado: assumia que todos os stubs eram `null`.
  Agora aceita `clean_code` e `env_check`. O Cofre deve encontrar o mesmo teste; possível conflito
  trivial no merge dessas 4 linhas.

## Pendências e avisos para o sênior

- **Fase A — `parameters` das ferramentas extras:** os providers (`openai-compatible.js`,
  `anthropic.js`) leem `tool.parameters`, mas o formato das ferramentas extras usa
  `definition.input_schema`, que `tools.js` repassa sem converter. `clean_code` declara o schema
  nos dois campos (o e2e confere que chega ao modelo); `env_check` do Cofre precisa do mesmo cuidado,
  ou `tools.js` deve mapear `input_schema → parameters`.
- **Cartão de aprovação do agente (`agent-ui.js`):** sem `preview.diff`, uma ferramenta de escrita
  com `input.path` aparece como "Apagar este caminho?". `clean_code` sempre manda um diff (para pasta,
  combinado) para evitar isso; o ideal seria o `agent-ui` mostrar `preview.files`.
  O passo do agente também não mostra o `summary` de ferramentas extras em `.ag-step-meta`.
- **`editIds` parciais:** escolher só algumas edições pode quebrar o código quando um import é
  considerado não usado porque o único uso estava num `console.log` também marcado. A UI sempre aplica
  todas as edições do arquivo; só a API permite subconjunto.
- Status bar do arquivo ativo: detecção da troca de aba por verificação de `State.activePath` a cada
  300 ms (não há evento de troca de aba no editor).
- O status bar e os badges analisam o conteúdo **do disco**, não o texto não salvo do editor.
- Medição de RAM (F0.5) fica com o sênior na Tarefa 16.

## Correções da revisão

Commit `fdcd3ed` (branch `feat/v1.1.0-fix-broom`). Princípio: a Vassoura nunca pode quebrar
código; na dúvida, não remove.

1. **Código morto × içamento** (`visitStatements`, `deadIf`).
   - Depois de `return`/`throw`/`break`/`continue` nunca saem declarações: `var`/`let`/`const`,
     `function`, `class`, `type`, `interface`, `enum`, `namespace`/`module`, `import`/`export`,
     nada com `declare`. Também fica qualquer instrução que contenha `var` ou declaração de função
     sem entrar em outra função/classe (ex.: `for (var i…)` morto).
   - `let`/`const`/`class` também ficam (mais conservador que a revisão pedia): removê-los muda a
     resolução de nomes de closures (TDZ → global) e, em TS, `class` é tipo içado.
   - `if (0)`/`if (false)`: se o bloco morto tem `var`/`function`, o `if` inteiro fica.
   - Extra: `if (0) {…} else { let a … }` antes desembrulhava o `else` e podia colidir com um `let a`
     externo; agora, com `let`/`const`/`class`/`function`/tipos no nível do `else`, as chaves ficam.
2. **Fábrica JSX** (`unusedInImport`, novo `jsx-config.js`). Com JSX no arquivo, nunca saem `React`,
   `h`, `createElement`, `Fragment`, `jsx`, `jsxs`, `jsxDEV`, os nomes de `@jsx X`/`@jsxFrag Y` em
   qualquer comentário, nem o identificador-raiz de `jsxFactory`/`jsxFragmentFactory` (ex.:
   `preact.h` → `preact`) do `tsconfig.json`/`jsconfig.json` mais próximo. A busca roda no worker:
   sobe da pasta do arquivo até achar o config, uma pasta com `.git` ou a raiz do disco; segue
   `extends` relativo (até 5 níveis); cache por pasta enquanto o worker vive.
3. **`console.*` com efeito colateral.** Só sai se todos os argumentos forem livres de efeito
   (`isPure`): literais, identificadores, `this`, `import.meta`, acesso a propriedade/elemento
   (inclusive `?.`), template sem tag com partes livres, `!`/`-`/`+`/`~`/`typeof`/`void`,
   binários não-atribuição, condicional, arrays/objetos literais (sem spread), arrow/function e
   casts TS. Chamada, `new`, `await`, `yield`, atribuição, `++`/`--`, `delete`, spread, tagged
   template e expressão de classe (blocos `static` executam) → mantém. Sem "aviso" na UI.

Testes novos em `test/unit/broom-analyze.test.js` (12): casos da revisão, conferindo parse e
comportamento (JS executado em `vm` antes/depois) e o tsconfig em pasta temporária com `extends`
e comentários. Varredura de idempotência das fixtures continua verde.
Resultado: `npm run check` 646 pass / 0 fail; `test/e2e/broom.spec.js` 9 passed.

Avisos:
- O cache de análise do main (path+mtime+tamanho+regras) não observa o `tsconfig.json`; mudar a
  fábrica JSX só reflete após editar o arquivo ou reiniciar o app. O cache de pastas do worker some
  quando ele encerra por ociosidade (20 s).
- Getters em acesso a propriedade podem ter efeito; aceito como "livre" conforme a revisão.
- O motor não conhece a raiz do workspace; o limite da subida é `.git` ou a raiz do disco.
