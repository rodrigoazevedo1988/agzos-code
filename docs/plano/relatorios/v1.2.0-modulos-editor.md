## Entregas

Os quatro módulos ficam em `src/renderer/scripts/mods/`. Cada um tem um card no hub com liga/desliga e opções em Configurações → Módulos Agzos. O `app.js` chama `setupEditorMods()` (em `mods/index.js`) uma vez, depois do editor. A falha de um módulo não derruba os outros.

Peças comuns:
- `mods/common.js` traz `modSettings`, `isModEnabled`, `setModSetting` e `onModSettings`. Também monta a view do card (`mountModView`), com o interruptor `input.mod-enabled-toggle` e o botão "Opções nas Configurações".
- O CSS fica em `styles/editor-mods.css`.

### X1a — Agzos Erros na Linha (`inlineErrors`)
- `mods/inline-errors-core.js` é a parte pura. A função `inlineErrorItems(markers, opts)` gera uma decoração por linha, com o marcador mais grave. Ela filtra por severidade (`error`, `warning`, `info`; dicas nunca entram), atende a opção "só na linha do cursor" e deixa a mensagem em uma linha, truncada com `…`.
- `mods/inline-errors.js` usa a decoração `after` do Monaco, com a classe `agzos-inline-error-<severidade>` e a cor da severidade (com variante para o tema claro). O `hoverMessage` mostra a mensagem inteira. A decoração é atualizada quando:
  - os marcadores mudam (`onDidChangeMarkers`);
  - o modelo troca;
  - o cursor se move, se a opção "só na linha do cursor" estiver ligada;
  - as configurações mudam.
- Configuração: `{ enabled: true, severities: ['error','warning'], onlyCursorLine: false }`.

### X1b — Agzos Erros Claros (`prettyErrors`) e painel Problemas
- `mods/format-ts-error.js` é a parte pura:
  - `formatTsMessage(text)` devolve `{ blocks }`, com um bloco por linha da cadeia de mensagens e a indentação de cada uma. Os trechos entre aspas viram partes `type`.
  - `prettyType` quebra objetos de tipo longos em linhas indentadas e respeita strings literais.
  - `tsErrorCode(code)` devolve `TS<n>` com o link `https://typescript.tv/errors/#ts<n>`.
  - `tsErrorMarkdown()` gera o markdown do hover, com tipos em código e blocos ```` ```typescript ```` para tipos longos. O Monaco realça esses blocos.
- `mods/pretty-errors.js` registra um `HoverProvider` para `typescript` e `javascript` que só responde a marcadores dos donos `typescript` e `javascript`. O hover padrão do Monaco continua aparecendo acima, com a mensagem crua.
- `mods/problems-panel.js` é novo. Antes o `#pane-problems` era estático ("Sem problemas."). Agora ele lista os marcadores do arquivo ativo:
  - a ordem é por severidade e depois por linha;
  - clicar ou dar Enter leva à posição do problema;
  - com Erros Claros ligado, as mensagens de TS/JS aparecem formatadas, com tipos realçados por `monaco.editor.colorize` e o código do erro como link (`a.problem-code`, que abre no navegador pelo `setWindowOpenHandler`).

### X1c — Agzos Marca-texto (`highlighter`)
- `mods/highlight-tags.js` é a parte pura:
  - `parseTags(["marcador=#cor"])` lê a lista de marcadores; o marcador `//` é sempre riscado.
  - `findTaggedComments(text, languageId, tags)` devolve ranges no formato do Monaco.
  - Comentários reconhecidos, conforme a linguagem: `//`, `#`, `--`, `/* */` e `<!-- -->`.
  - Aberturas de comentário dentro de strings são ignoradas, incluindo strings triplas do Python e `${#arr}` do shell.
  - Nos blocos, um marcador logo após a abertura destaca o bloco todo. Um marcador numa linha interna (depois de `*`) destaca só aquela linha. No JSDoc (`/**`), o segundo `*` não conta como marcador.
  - Marcadores-palavra (TODO, FIXME) não diferenciam maiúsculas e exigem um separador depois (`TODOS` não casa).
- `mods/highlighter.js` gera uma classe CSS por marcador (`<style id="agzos-hl-style">`) e aplica com `inlineClassName`. Arquivos acima de 1 MB não são analisados.
- Configuração: `{ enabled: true, tags: ['!=#FF5252','?=#4FC3F7','TODO=#FF9800','FIXME=#FF9800','*=#98C379','//=#7A7A7A'] }`. Nas Configurações, a lista é editada como texto separado por vírgula. A normalização descarta itens com cor inválida.

### X1d — Agzos Formatador (`formatter`)
- `src/main/modules/formatter/config.js`:
  - `readPrettierConfig(dir, { root })` segue a ordem de busca do próprio Prettier e sobe da pasta do arquivo até a raiz da janela. Sem raiz, olha só a própria pasta.
  - Lê apenas `.prettierrc` (JSON ou YAML simples), `.prettierrc.json`, `.prettierrc.yaml`, `.prettierrc.yml` e `package.json#prettier` (quando é objeto).
  - `.js/.cjs/.mjs/.ts/.mts/.cts` e `prettier.config.*` devolvem `{ config: null, ignored, warning }` e nunca são lidos como código.
  - Uma config compartilhada (string no `package.json`), `.json5`, `.toml`, JSON inválido e YAML aninhado são ignorados com aviso.
  - `sanitizeOptions` aplica uma lista branca de opções e tipos: `plugins`, `filepath` e chaves desconhecidas nunca passam, e `parser` só aceita os parsers embutidos.
  - `optionsForFile` aplica `overrides` (com `files` e `excludeFiles` por glob) e passa as opções de cada override pela mesma lista branca.
- `src/main/modules/formatter/worker.js` define `format({ text, filepath?, languageId?, options })`. O parser é escolhido pela extensão ou pela linguagem, e o prettier é carregado sob demanda. O handler `formatter.format` fica no `src/main/modules/worker.js` existente.
- `src/main/ipc/formatter.js` define o canal `formatter:format({ path, text, languageId, tabSize, insertSpaces })`:
  - o caminho passa pelo guard da janela (`guardFor(sender)`) e é recusado se tiver `\0`;
  - a base vem do editor (`tabWidth`, `useTabs`), e a config do projeto vence;
  - recusa o pedido se o módulo estiver desabilitado;
  - usa o `modulesWorker` do `main.js`. O preload expõe `window.agzos.formatter.format`.
- `mods/formatter.js` registra um `DocumentFormattingEditProvider` para JS, TS, JSON, CSS, SCSS, LESS, HTML, Markdown e YAML. JSX e TSX entram pelas linguagens `javascript` e `typescript`.
  - Com o módulo ligado, os formatadores de documento embutidos (CSS, HTML e JSON) são desligados por `setModeConfiguration({ documentFormattingEdits: false })`. Assim o Prettier sempre vence. O TS do Monaco só tem formatador de trecho, que fica "sintético" e perde para o real.
  - Com o módulo desligado, os providers são descartados e os do Monaco voltam. O e2e confere a diferença na saída de CSS.
  - O comando "Formatar Documento", Shift+Alt+F e o menu do Monaco usam o provider sem nenhuma mudança no comando.
  - Avisos de config ignorada aparecem uma vez como toast. Erros de sintaxe viram toast "Agzos Formatador: …".
- "Formatar ao salvar" por linguagem: em `editor.js` entrou só `setFormatOnSaveCheck(fn)`. O `saveFile` formata quando `editor.formatOnSave` está ligado ou quando o check do módulo diz que sim.
- Configuração: `{ enabled: true, formatOnSave: { javascript, typescript, json, css, scss, less, html, markdown, yaml: false } }`.

### Configurações
- `src/main/lib/settings.js` tem `normalizeEditorMods(v)`, chamado dentro de `normalizeModules`. Valores inválidos voltam ao padrão campo a campo. O espelho dos padrões fica em `settings-modal.js`.
- Itens novos em Configurações → Módulos Agzos, com uma subseção por módulo. Os campos de lista (severidades e marcadores) usam o tipo `list` que já existia.

## Foco de revisão 5 (X1)

Um projeto com `.prettierrc.js` ou `prettier.config.mjs` é ignorado com aviso, e nenhum código do projeto executa:
- `config.js` só lê arquivos de dados e nunca chama `require`/`import` sobre o projeto;
- o worker nunca chama `prettier.resolveConfig`;
- `plugins` é removido em todos os níveis;
- `parser` só aceita os parsers embutidos;
- o prettier usado é sempre o do app, nunca o `node_modules` do projeto.

Os testes com arquivo-marcador cobrem config em código, plugin nas opções e IPC.

## Desvios e observações

- **Painel Problemas:** foi implementado aqui porque estava estático e a spec pede Erros Claros "no painel Problemas". O painel mostra só o arquivo ativo, porque o editor tem um modelo por vez.
- **Hover dos Erros Claros:** é um hover adicional. O hover padrão do Monaco com a mensagem crua continua aparecendo, porque o Monaco não permite substituí-lo sem reescrever os marcadores, o que afetaria o `get_problems` do agente.
- **Marcadores do Marca-texto:** ficam guardados como strings `"marcador=#cor"`, não como objetos, para caber no editor de lista das Configurações. O riscado é fixo no marcador `//`.
- **Severidades:** são editadas como lista em inglês (`error, warning, info`), porque não há controle de múltipla escolha nas Configurações.
- **Opções do Formatador:** o YAML aceito é só o plano (`chave: valor`); `overrides` em YAML é recusado com aviso. O `.prettierignore` não é considerado (fora do escopo da spec).
- **Pacote:** o prettier carrega os plugins embutidos por `import()` dinâmico dentro do processo utilitário. Vale conferir no build empacotado (asar) na integração.
- **Unit instável:** durante o trabalho, `npm run check` mostrou 1 falha intermitente duas vezes, com outros agentes rodando em paralelo. Ela não se repetiu em 6 execuções seguidas, e não consegui identificar qual teste falha.
