# Agzos Code 1.2.0 — Pasta remota SSH, Snippets, Git Slider e Módulos Agzos

Data: 2026-11-17 · Decisões tomadas com o usuário em chat.
Origem: PRD "Utilidades Nativas" v1.1 (onda 2) + backlog "Módulos Agzos — próximos".

## Decisões

- **Pasta remota via SSH completa:** explorer, editor, visualizadores, terminal, busca, Quick Open, painel Git e agente funcionam na pasta remota como numa local.
- **Senha SSH:** chaves do `~/.ssh` e agente SSH primeiro; se o host pedir senha, o app pergunta e oferece "Lembrar no cofre do sistema" (mesmo cofre dos tokens).
- **Snippets:** biblioteca já vem com cerca de 20 componentes Agzos (HTML + Tailwind) editáveis; armazenamento em JSON no `userData` (decisão da 1.1.0).
- **Módulos extras nesta versão:** Agzos Erros na Linha, Agzos Erros Claros, Agzos Marca-texto, Agzos Árvore, Agzos Snap, Agzos Formatador e Agzos Ao Vivo.
- Fora: Sandbox de Componentes (1.3.0) e os demais módulos do backlog.

Restrições herdadas: `contextIsolation`, guard por janela em todo caminho, nada de módulo nativo que precise compilar (dependência nativa só se opcional e com fallback JS), textos pt-BR, testes unitários + e2e, opções em Configurações → Módulos Agzos, cards no hub Módulos Agzos, ferramentas para o agente quando fizer sentido.

## R — Pasta remota via SSH

### Conexão (`src/main/remote/`)
- Biblioteca `ssh2` (JS puro; a dependência opcional `cpu-features` não é necessária e não pode quebrar o build se faltar).
- `connection.js`: abre conexão por alias do `~/.ssh/config` (reusa `src/main/lib/ssh-config.js`: `HostName`, `User`, `Port`, `IdentityFile`) ou por `usuario@host[:porta]`. `ProxyJump`/`ProxyCommand` não suportados nesta versão: mensagem clara.
- Autenticação, nesta ordem: agente SSH (`SSH_AUTH_SOCK`; no Windows, pipe do OpenSSH `\\.\pipe\openssh-ssh-agent` e depois Pageant), chaves do `IdentityFile`/padrão (`id_ed25519`, `id_rsa`…; passphrase pedida ao usuário), senha. Senha/passphrase pedida em diálogo do app com checkbox "Lembrar no cofre do sistema" → cofre `ssh.<user>@<host>:<porta>`. Senha errada salva é apagada e pedida de novo.
- **Host key:** confere com `~/.ssh/known_hosts` (hashes `|1|` inclusos). Desconhecida → diálogo com o fingerprint SHA256 e "Confiar e conectar" (acrescenta ao `known_hosts`). Divergente → bloqueia com aviso de possível ataque, sem opção de continuar.
- Keepalive 15 s. Queda → faixa no topo "Conexão com <host> perdida — Reconectar" (tenta sozinho 3 vezes com espera crescente); buffers não salvos ficam no editor.
- Uma conexão por host por janela, compartilhada por SFTP, terminais, exec e busca.

### Workspace remoto
- Pasta remota identificada por URI `ssh://<alias-ou-user@host:porta>/<caminho absoluto>`. Abrir: botão remoto da status bar → "Abrir pasta remota via SSH" (deixa de ser "Em breve") → escolhe o host → navegador de pastas remoto (SFTP) → abre na janela atual ou em nova janela.
- Título da janela e status bar mostram `SSH: <host>`. "Abrir Recente" lista pastas remotas.
- **Provider de workspace** (`src/main/workspace/providers/{local,ssh}.js`) com a mesma interface: `readDir`, `readFile`, `readBinary`, `createReadStream(path,{start,end})`, `writeFile`, `stat`, `mkdir`, `remove`, `rename`, `exists`, `exec(cmd, args, { cwd, env, signal, onData, timeoutMs })`, `spawnShell({ cols, rows, cwd })`. Os IPCs de arquivo, busca, git, agente, Vassoura, Cofre e visualizadores escolhem o provider pelo caminho (`ssh://` → ssh). O guard por janela passa a aceitar a raiz remota pelo prefixo da URI (sem `..`, normalização POSIX).
- Explorer, editor, abas, Quick Open (lista via `rg --files` remoto, ou `find` com exclusões, limite 20 mil), visualizadores (protocolo `agzos-file` serve remoto via stream SFTP com Range).
- Arquivos abertos: verificação de mudança externa por `stat` a cada 5 s (sem watcher remoto).
- **Terminal:** sessão nova numa pasta remota abre shell no host (`shell` do ssh2, `xterm-256color`, já em `cd` na raiz, com aspas seguras); perfil "SSH: <host>" na lista.
- **Busca em arquivos:** `rg --json` no host se existir, senão `grep -rIn` com as mesmas exclusões; resultados no painel de busca.
- **Git:** o runner do git roda via `exec` do provider (`git -C <raiz> …`). Push/pull/fetch remotos usam as credenciais do próprio host; o token do GitHub do cofre **não** é enviado ao host remoto (ficaria visível em `ps` lá). Publicar repo/criar PR continuam via API do GitHub no main.
- **Agente:** ferramentas de arquivo, busca e `run_command` operam no host via provider; checkpoints guardam o conteúdo original localmente. Regras de risco e aprovação iguais às locais.
- Cofre `.env` e Vassoura funcionam via provider (a Vassoura lê o conteúdo e analisa localmente no worker).

### Testes
- Unit: parser de `known_hosts` (hash `|1|`, portas `[host]:22`), ordem de autenticação, URI ↔ caminho, guard remoto (`..`, encoding), provider ssh com servidor fake (`ssh2` `Server` + SFTP em memória ou pasta temporária).
- E2E: servidor SSH de teste local (fixture com `ssh2` `Server`, chave gerada no teste) — abrir pasta remota, listar, editar e salvar, abrir imagem, terminal remoto ecoando, busca, `git status` remoto, host key desconhecida pede confirmação, divergente bloqueia, queda mostra "Reconectar".

## S — Snippets de Agência (`src/main/modules/snippets/`)

- Armazenamento `userData/snippets.json` (`{ version, snippets: [{ id, name, category, language: 'html'|'jsx'|'css'|'tailwind', body, tags, createdAt, updatedAt, builtin? }] }`). Escrita atômica (tmp + rename).
- **Biblioteca inicial (~20)** em `src/main/modules/snippets/seed/`: Hero (3), CTA (3), Formulário (contato, newsletter, login), Pricing (2), Prova social (depoimentos, logos), Features (2), FAQ, Rodapé (2), Navbar (2), Card de produto, Banner de cookies. HTML + Tailwind, responsivos e acessíveis, identidade Agzos. Restaurar originais disponível.
- **Variáveis da marca** em Configurações → Módulos Agzos → Snippets: `cor_primaria` `#D10A11`, `cor_fundo` `#0E0E0E`, `cor_texto` `#E8E8E8`, `cor_secundaria`, `fonte` `Inter, sans-serif`, `nome_marca` `Agzos`, `url_site`, `email_contato` (lista editável; o usuário pode criar variáveis). Interpolação `{{nome}}`; variável desconhecida fica como está.
- **View no hub:** busca, filtro por categoria, grade de miniaturas (iframe `sandbox` com `srcdoc`, Tailwind embutido do pacote `@tailwindcss/browser` vendorizado, renderizado só quando visível), clique = inserir no cursor, arrastar para o editor = inserir no ponto de soltura, menu (editar, duplicar, apagar, copiar). Editor de snippet: nome, categoria, linguagem, corpo (Monaco) e prévia ao vivo.
- **Inserção** < 100 ms; em arquivo `.jsx/.tsx`, HTML vira JSX (`class`→`className`, `for`→`htmlFor`, `style` string → objeto simples, tags vazias fechadas).
- "Salvar seleção como snippet" no menu do editor; importar/exportar JSON.
- Ferramentas do agente: `list_snippets` (read), `insert_snippet(id, path, line?)` (write), `save_snippet(name, category, language, body)` (write).
- Testes: unit (interpolação, HTML→JSX, store atômico, seed válido, busca); e2e (inserir por clique e por arrastar, variável trocada, criar/editar/apagar, agente salva snippet).

## H — Histórico local e Git Slider (`src/main/modules/history/`)

- **Histórico local:** a cada salvamento (e antes de alterações do agente, da Vassoura e do Cofre), guarda uma cópia em `userData/local-history/<sha1(caminho)>/<timestamp>` + `index.json` (caminho, tamanho, origem: `salvar|agente|vassoura|cofre|externo`). Limites: 50 versões por arquivo, 30 dias, 300 MB no total (apaga as mais antigas), ignora binários e arquivos > 1 MB. Funciona para arquivos remotos (cópia local). Pasta 0700, arquivos 0600.
- **Git Slider:** barra "Linha do tempo" acima do editor do arquivo ativo (comando "Agzos: Linha do tempo do arquivo", `Ctrl+Alt+H`, botão na barra das abas). Marcadores = commits (`git log --follow -n 200 --format=… -- <arquivo>`) + versões do histórico local, em ordem de tempo, com rótulo (autor, mensagem, data relativa, origem).
- Arrastar/clicar mostra o diff (editor de diff do Monaco, somente leitura) entre aquela versão e o presente; botões "Restaurar esta versão" (escreve com checkpoint e entra no histórico), "Comparar com a anterior", "Voltar ao presente" (`Esc`). Setas ←/→ navegam.
- Conteúdo de commit via `git show <sha>:<caminho relativo>`; cache LRU de 50 MB por janela; carregamento em segundo plano, sem travar o editor; repositório grande: só os 200 commits mais recentes.
- Ferramenta do agente: `file_history(path)` (read): lista versões (commits + local) sem conteúdo.
- Testes: unit (limites e poda, índice, merge commits+local, parser do log); e2e (salvar 3 vezes → 3 marcadores, slider mostra diff, restaurar, Esc volta; arquivo em repo git mostra commits).

## X — Módulos Agzos extras

Cada um tem card no hub (com liga/desliga) e opções em Configurações → Módulos Agzos.

- **Agzos Erros na Linha:** mensagem do erro/aviso no fim da linha (decoração `after` do Monaco, cor por severidade, truncada com reticências; hover mostra inteira). Opções: severidades (erro/aviso/info), mostrar só na linha do cursor.
- **Agzos Erros Claros:** mensagens do TypeScript/JavaScript reformatadas no hover e no painel Problemas: tipos longos quebrados e indentados, trechos de tipo realçados (`monaco.editor.colorize`), código do erro com link para a documentação (`https://typescript.tv/errors/#ts<code>`).
- **Agzos Marca-texto:** comentários coloridos por marcador: `!` alerta (vermelho), `?` dúvida (azul), `TODO`/`FIXME` (laranja), `*` destaque (verde), `//` duplo riscado (cinza). Reconhece `//`, `#`, `--`, `/* */`, `<!-- -->` conforme a linguagem. Lista de marcadores e cores editável.
- **Agzos Formatador:** formatação estilo Prettier com o pacote `prettier` (v3) embutido, num worker; lê `.prettierrc`/`.prettierrc.json`/`.prettierrc.yaml`/`prettier` do `package.json` do projeto (**nunca** executa config `.js` nem o prettier do projeto). "Formatar Documento" usa o Agzos Formatador nas linguagens suportadas (JS/TS/JSX/TSX/JSON/CSS/SCSS/LESS/HTML/Markdown/YAML) e o do Monaco nas demais. Opção "Formatar ao salvar" por linguagem.
- **Agzos Árvore:** no menu de contexto de pasta e na paleta, gera a árvore em texto (`├──`, `└──`) com opções (profundidade, respeitar `.gitignore`, só pastas, ocultar arquivos ocultos) e prévia; ações Copiar, Inserir no cursor e Criar `ARVORE.md`. Limite 5 mil entradas. Funciona em pasta remota. Ferramenta do agente `project_tree(path, depth)` (read).
- **Agzos Snap:** com seleção (ou arquivo inteiro), "Agzos Snap" abre um editor de imagem: tema, fundo (gradiente Agzos, sólido, transparente), padding, moldura de janela com título, números de linha, marca d'água opcional "Agzos Code"; exportar PNG (2x) por diálogo ou copiar para a área de transferência. Render com `monaco.editor.colorize` + `capturePage` numa janela oculta.
- **Agzos Ao Vivo:** "Abrir com Agzos Ao Vivo" em arquivo `.html` ou pasta: servidor HTTP local em `127.0.0.1` (porta livre a partir de 5500) que serve a pasta (só dentro do guard da janela), injeta um script de recarga nas páginas HTML e recarrega o navegador ao salvar (SSE). Item na status bar "Ao Vivo :5500" (clicar = parar/abrir); aparece na aba PORTAS; abre no navegador padrão. Em pasta remota: serve via provider.

Testes: unit para formatação de mensagens TS, parser de marcadores, gerador de árvore (`.gitignore`, profundidade), leitura de config do prettier (recusa `.js`), servidor Ao Vivo (guard, injeção, SSE); e2e para cada módulo (decoração aparece, hover formatado, árvore copiada, PNG gerado, formatar ao salvar, navegador recebe recarga).
