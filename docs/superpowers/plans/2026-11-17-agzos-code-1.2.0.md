# Agzos Code 1.2.0 — Plano de implementação

> **Para agentes executores:** SUB-SKILL OBRIGATÓRIA: superpowers:subagent-driven-development ou superpowers:executing-plans. Passos com checkbox (`- [ ]`).

**Objetivo:** pasta remota via SSH, Snippets, histórico local + Git Slider e 7 Módulos Agzos extras, na 1.2.0.

**Arquitetura:** cada frente é um módulo com motor puro no main (`src/main/modules/<id>/` ou `src/main/remote/`), IPC próprio em `src/main/ipc/<id>.js`, namespace no preload e UI em `src/renderer/scripts/<id>.js` + CSS próprio; card no hub (`registerModule`), opções em Configurações → Módulos Agzos, comandos via `registerCommands`.

**Stack:** Electron 32, Node 22, Monaco 0.50, `ssh2` 1.17, `prettier` 3.10, `@tailwindcss/browser` 4.3 (já instalados e no `package.json`), `node:test`, Playwright (`xvfb-run`).

**Spec:** `docs/superpowers/specs/2026-11-17-agzos-code-1.2.0-design.md` (os executores leem a spec e este plano).

## Restrições globais

- JS puro, `contextIsolation`, guard **por janela** (`src/main/lib/window-guards.js`, `guardOf(event.sender)`) em todo caminho. Nada de guard global.
- Sem dependências novas além das listadas. `node_modules` é symlink compartilhado nas worktrees: **nunca** rodar `npm install`/`npm i` (nem `--no-save`); nunca commitar o symlink (`git add` por caminho, nunca `-A`/`.`).
- Tudo que grava em `userData` com dados do usuário: pasta 0700, arquivos 0600.
- Textos pt-BR com acentos. Nomes de módulo: "Agzos <Nome>".
- Settings novas em `settings.modules.<chave>` com normalização em `src/main/lib/settings.js` (padrão de `normalizeModules`); valor inválido volta ao padrão campo a campo.
- Ferramentas do agente: `{ definition: { name, description, input_schema }, kind, prepare(input, ctx) }` registradas em `src/main/modules/agent-tools.js`.
- Verificação: `npm run check` + e2e do módulo; no fim, a suíte e2e inteira. Commits pt-BR `feat(<módulo>): …` com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ao apagar arquivos: caminhos explícitos, nunca glob.
- Arquivos compartilhados (`index.html`, `app.js`, `preload.js`, `main.js`, `settings.js`, `settings-modal.js`, `modules-hub.js`, `agent-tools.js`): só **acréscimos** pequenos e localizados, para o merge ser simples. No `modules-hub.js`, troque apenas o card "Em breve" do seu módulo, se houver.

## Foco de revisão

1. Host remoto com chave divergente no `known_hosts` → conexão bloqueada, sem botão de continuar (Tarefa R1).
2. Arquivo remoto com nome com espaço, aspas, `$()` ou `;` → nenhum comando remoto monta string de shell sem aspas seguras (R2).
3. Snippet com `</script>` ou `onerror=` na miniatura → iframe `sandbox` sem `allow-same-origin` e CSP; nada executa no app (S).
4. Histórico local com arquivo de 0 byte, CRLF e acentos no caminho → versão salva e restaurada byte a byte (H).
5. Projeto com `.prettierrc.js` ou `prettier.config.mjs` → ignorado com aviso; nenhum código do projeto executa (X1).

## R — Pasta remota via SSH

### R1: Conexão, autenticação e host key
- Criar `src/main/remote/{connection,known-hosts,auth,manager}.js`, `src/main/ipc/remote.js`, preload `window.agzos.remote`.
- `parseKnownHosts(text) → [{ hosts: string[]|{hashed, salt, hash}, keyType, key }]`; `checkHostKey(entries, host, port, keyType, keyBuffer) → 'match'|'unknown'|'mismatch'` (suporta `|1|salt|hash` e `[host]:porta`).
- `authOrder({ platform, env, identityFiles }) → [{ type: 'agent', agent }|{ type: 'key', path }|{ type: 'password' }]` (agente: `SSH_AUTH_SOCK`; win32: `\\.\pipe\openssh-ssh-agent`, depois `pageant`).
- `manager.connect(target, { askSecret, askHostKey, signal }) → Connection` (uma por host por janela, keepalive 15 s, reconexão 3 tentativas). `askSecret`/`askHostKey` são diálogos no renderer via IPC (`remote:prompt` → `remote:prompt:reply`, presos ao `webContents` dono). Senha "Lembrar" → cofre `ssh.<user>@<host>:<porta>`.
- Testes unit: known_hosts (hash, porta, mismatch), ordem de auth, senha salva errada é apagada; servidor de teste com `ssh2` `Server` (fixture `test/fixtures/ssh-server.js`, chave gerada no teste) — conecta com chave, com senha, host desconhecido pergunta, divergente bloqueia.
- Commit `feat(remoto): conexão SSH, autenticação e verificação de host`.

### R2: Provider de workspace e pasta remota
- Criar `src/main/workspace/providers/{local,ssh}.js` com a interface da spec e `src/main/workspace/provider-for.js`: `providerFor(pathOrUri, sender) → provider`; `isRemote(p)`; `parseRemoteUri('ssh://host/x') → { target, path }`.
- `window-guards.js`/`path-guard.js`: raiz remota aceita por prefixo de URI normalizada POSIX (`..`, `%2e%2e`, barra dupla negados).
- Rotear por `providerFor`: `ipc/fs.js` (todos os canais), `ipc/workspace.js` (abrir pasta remota, recentes `ssh://`), Quick Open/listagem (`rg --files`/`find` remoto, limite 20 mil), busca (`rg --json` → `grep -rIn`), `lib/file-protocol.js` (stream SFTP com Range), verificação de mudança externa (stat 5 s).
- Comandos remotos sempre com argumentos em array e aspas POSIX seguras (`'` → `'\''`) quando precisar de shell (`cd <raiz> && …`).
- UI: botão remoto → "Abrir pasta remota via SSH" (navegador de pastas SFTP, abrir aqui/nova janela); título e status bar `SSH: <host>`; faixa "Conexão perdida — Reconectar".
- Testes unit (URI, guard remoto, aspas), e2e com o servidor fixture (abrir pasta, listar, editar/salvar, imagem via protocolo, busca, Quick Open, mudança externa recarrega).
- Commit `feat(remoto): pasta remota com explorer, editor, busca e visualizadores`.

### R3: Terminal, Git e agente remotos
- Terminal: perfil/sessão SSH na pasta remota via `spawnShell` do provider (canal `shell`, resize), roteado em `ipc/term.js` sem quebrar o PTY local.
- Git: `src/main/git/run.js` executa via `provider.exec` quando a raiz é remota; token do GitHub não é injetado em host remoto (teste garante que `http.extraheader` não aparece nos args remotos).
- Agente: ferramentas de arquivo/busca/`run_command` via provider; checkpoints locais; Vassoura e Cofre via provider (conteúdo lido remoto, análise local).
- E2E: terminal remoto ecoa; `git status`/commit remoto; agente fake edita arquivo remoto.
- Relatório `docs/plano/relatorios/v1.2.0-remoto.md`. Commit `feat(remoto): terminal, git e agente na pasta remota`.

## S — Snippets

### S1: Store, seed e interpolação
- `src/main/modules/snippets/{store,interpolate,jsx,seed/*.json}.js`; IPC `src/main/ipc/snippets.js`; preload `window.agzos.snippets.{list,get,save,remove,duplicate,restoreDefaults,import,export}`.
- `interpolate(body, variables) → string` (`{{nome}}`, desconhecida fica); `htmlToJsx(html) → string` (`class`, `for`, `style` string → objeto, tags vazias fechadas, comentários `{/* */}`).
- ~20 snippets seed conforme a spec (HTML + Tailwind, responsivos, acessíveis, sem imagens externas — use SVG/gradientes).
- Testes unit: interpolação, JSX (fixtures), store atômico (tmp+rename, 0600), seed válido (HTML parseável, sem `<script>`).

### S2: View, miniaturas e inserção
- Vendorizar `@tailwindcss/browser/dist/index.global.js` via `tools/setup-vendor.js`.
- `src/renderer/scripts/snippets.js` + `styles/snippets.css`: busca, categorias, grade de miniaturas (iframe `sandbox="allow-scripts"` sem `allow-same-origin`, `srcdoc` com CSP `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'` só para o Tailwind embutido, renderizado com IntersectionObserver), clique insere no cursor, arrastar para o Monaco insere no ponto, editor de snippet com prévia ao vivo, "Salvar seleção como snippet", importar/exportar.
- Configurações → Módulos Agzos → Snippets: variáveis editáveis (lista nome/valor).
- E2E: inserir por clique e arrastar, variável trocada, `.tsx` recebe JSX, criar/editar/apagar/restaurar.

### S3: Ferramentas do agente
- `list_snippets` (read), `insert_snippet` (write, com checkpoint), `save_snippet` (write). E2E com agente fake. Relatório `docs/plano/relatorios/v1.2.0-snippets.md`.

## H — Histórico local e Git Slider

### H1: Histórico local
- `src/main/modules/history/{store,prune}.js`, IPC `src/main/ipc/history.js`, preload `window.agzos.history.{list,read,restore,clear}`.
- Gatilhos: salvar (renderer chama após `saveFile`), e antes de escritas do agente/Vassoura/Cofre (função `recordBefore(absPath, origin)` exportada e chamada nos pontos de escrita existentes).
- Limites da spec, poda por arquivo/idade/total; binários e > 1 MB ignorados; 0700/0600.
- Testes unit: poda, 0 byte, CRLF, acentos no caminho, restauração byte a byte.

### H2: Linha do tempo (Git Slider)
- `src/main/modules/history/timeline.js`: `parseGitLog(text) → commits`, `mergeTimeline(commits, local) → items`; conteúdo de commit via `git show <sha>:<rel>` (runner existente), cache LRU 50 MB.
- UI `src/renderer/scripts/timeline.js` + CSS: barra acima do editor, marcadores, diff somente leitura, Restaurar (com checkpoint + entra no histórico), Comparar com anterior, ←/→, Esc; comando `Ctrl+Alt+H` e botão na barra das abas.
- E2E: 3 salvamentos → 3 marcadores; repo git → commits; restaurar; Esc.

### H3: Ferramenta do agente e relatório
- `file_history(path)` (read). Relatório `docs/plano/relatorios/v1.2.0-historico.md`.
